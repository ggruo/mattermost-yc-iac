# 2. VPC, security groups и VM вручную

## Цель и подготовка

После IAM. Схема: интернет → public IP VM → Nginx:80.
Private IP используется внутри VPC, public IP — для внешней связи.
Subnet привязана к зоне; SG фильтрует доступ и не выдаёт IP.

Команды выполняйте из корня репозитория в **bash** (на macOS сначала `bash`).
`REPLACE_*` — значение, которое нужно заменить; не выполняйте его буквально.
`export` действует только в текущем терминале. Секреты не вставляйте в команды.

## Время и стоимость

2–3 часа: VM 2 CPU/2 GB, SSD 15 GB, public IP; далее добавится PG.
Используйте Ubuntu 24.04 LTS и standard-v3.
Перед созданием внесите оценку в [таблицу бюджета](00-setup.md#бюджет).

## В UI

1. VPC: сеть `manual-net`, subnet `manual-a`, зона ru-central1-a,
   CIDR 10.10.10.0/24. Не выбирайте автоматические сети других проектов.
2. SG `manual-vm`: входящие TCP 22 от вашего публичного IP/32,
   TCP 80 от 0.0.0.0/0, исходящие ANY к 0.0.0.0/0.
3. Compute: VM `manual-vm`, указанные размеры, выбранная subnet и SG,
   публичный IPv4, пользователь ubuntu, содержимое `~/.ssh/yc-course.pub`.
4. Посмотрите private/public IP, boot disk, операции запуска. Скопируйте public IP.
   Вкладка мониторинга полезнее CLI для первого знакомства с CPU/диском.

## В терминале

```bash
export VM_IP=REPLACE_PUBLIC_IP
ssh -i ~/.ssh/yc-course ubuntu@"$VM_IP"
```

На VM (после проверки fingerprint SSH):

```bash
sudo apt-get update
sudo apt-get install -y nginx postgresql-client
sudo systemctl enable --now nginx
ip address
ip route
sudo ss -lntp
exit
```

Локально:

```bash
curl --connect-timeout 5 "http://$VM_IP"
```

Ожидается стартовая страница Nginx. `ss` показывает сокет процесса, SG — внешний
фильтр: открытый сокет сам по себе не делает сервер доступным.

## В коде

Пока ничего не применяйте через OpenTofu. Найдите соответствующие ресурсы
в `terraform/vm/main.tf`: сеть, subnet, SG, image, VM, IP. Вручную вы создаёте
учебные аналоги, не объекты с теми же именами/state.

## Проверка, поломка и вопросы

Удалите в UI только правило TCP 80: новый curl с timeout должен завершиться
ошибкой. SSH продолжает работать. Верните правило и повторите curl.
Если SSH недоступен, проверьте свой внешний IP, SG интерфейса, имя пользователя,
ключ и состояние VM — не разрешайте SSH всему интернету.
Объясните, почему private IP VM нельзя использовать из домашней сети без маршрута.

## Очистка и продолжение

Если сразу выполняете [PostgreSQL](03-postgresql.md), оставьте VM только на эту
сессию. Иначе в UI удалите VM вместе с boot disk, освободите public IP,
удалите SG, subnet, сеть. В начале следующего занятия повторите шаги создания.
